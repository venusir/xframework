# 模块审计

**判据清单、探针命令与报告格式的唯一真相在 `Documentation/ModuleAudit.md`——先读它。** 本文件只是入口：流程与顺序，内容不复制。

## 四步

1. **普查**：模块的文件清单、公开面、依赖方向、消费方（谁在用它的什么）、测试覆盖到哪。范围大时用 Explore 子代理并行——这一步不需要判断力，只需要「全」。
2. **判据逐类扫**：按手册第三节的清单逐类问（清单会随每轮审计新增类别，别记条数）。不必每类都命中，但**每类都要留下「扫过了、无问题」的痕迹**——否则报告无法区分「没找到」与「没看」。
3. **定向验证**：可疑点必须落到证据上。
   - 只有编译器知道答案的 → **写独立复现程序编译验证**（重载决议、二义、cast 行为），并配一个**负向控制**证明验证程序真有判别力
   - 只有第三方知道答案的 → **读它的源码**（例：UniTask 的 `Forget()` 把异常交给谁）
   - 只有仓库知道答案的 → **跑门禁**
   - 纪律见 `Documentation/Workflow.md` §三：「改前必红」与「区分实测与推理」
4. **报告与拆分**：按严重度排序 + 每条给理由 + **「不该做」也写成结论** + 第三方对照表 + 标明实测/推理；然后按提交纪律拆原子提交（计划批准即授权本阶段提交；公开 API 变更与破坏性变更两类例外须单独确认）。

## 本仓门禁（阶段收尾跑）

```bash
dotnet build <csproj> --artifacts-path "$env:TEMP\xfw-artifacts" -v q --nologo   # 0 error
pwsh -File Tools/run-tests.ps1                                                   # 全量双平台 0 失败
pwsh -File Tools/check-docs.ps1 -Enforce                                         # 文档门禁（XML 告警 0 + 全部源文件参与编译 + 全部条目有 .meta）
```

定向跑用 `-Filter <正则>` / `-Fixture <类名>`；**带 `-Filter` 且未显式 `-Platform` 时只跑 PlayMode**，`Tests/Editor/` 下的用例会假绿。

## 三条提醒（细节在手册里）

- **审计轮只产出清单，不动代码**；范围由人圈定后才进「计划 → 逐提交实现 → 提交」。
- **结论按收件人分流**：使用方要知道的进模块 README（`已知限制` / `设计取舍` / `接口承诺到哪为止`）；只有维护方要知道的（已评估未采纳、未决项）进 `Documentation/Modules/<模块>.md`。落点表见手册 §五。
- **涉及重载决议或公开面形状的结论，一律先写复现程序编译验证**再写进文档或提交信息——本仓有过一次「只看规范、未编译验证」的假结论被写进文档的教训。
