# 模块技术文档

> **收件人**：框架作者 + 下一轮审计者。**不是**使用文档。
> 使用方文档在 `Assets/XFramework/Runtime/<模块>/README.md`——已知限制、设计取舍、接口承诺、线程契约、性能代价一律留在那里，本目录**不复述、不复制**。
> **本目录不随 UPM 包发布**：它在仓库根 `Documentation/` 下，第三方在包内看不到它。
> 规则见 `CLAUDE.md` → 文档分层；审计结论的落点表见 `ModuleAudit.md` §五。

## 这里放什么

节名固定（逐字，见下表）；**没有内容的节不建**（按需创建，不搞空壳）。顺序按上表，新增节照此插入即可，**不以重排既有小节为目的**——顺序不进门禁，机械守卫只管两件事：决策台账存在、条目格式合法（见「决策台账的条目格式」末段）。

| 节 | 内容 | 先例 |
|---|---|---|
| 文件结构 | 模块的源文件清单与职责。只此一份，README 不再保留副本 | Asset / UI / File |
| 模块版本记录 | 模块独立成包时代的本地版本号——与包 `CHANGELOG.md` 的语义化版本**不是同一套** | Pool / Input / Config |
| 决策台账 | 本模块的「已做 / 未做 / 待裁 / 暂不做 / 不做 / 已推翻」条目——**格式与状态词见下节**，吸收原先的「已完成功能与未做」「已评估未采纳与未决」两节 | 全部模块 |
| 沿革与已否决形状 | 「旧实现…」「原先…」：当时形态 → 现状，带日期与提交号 | Reactive / Update |
| 迁移指南 | 破坏性 API 变更的升级路径 | Data（v1 Table → v2 Block） |
| 审计轮次 | 过程性记录：扫了哪些判据、实测 vs 推理、本轮产出 | Lock / Localization |
| 实测记录 | 探针 / 基准的原始观察与结论（登记 2026-10-15：三个文件在用，形态一致） | Audio / Reactive / Timer |
| 与其它模块的边界 | 跨模块接缝的成文约定；下一轮审计时先看这里 | Audio / Log / Timer |
| 命名沿革 | 命名候选与否决理由，防下一轮重提 | Event |
| 带日期的过程记录 | 一次性过程留档，形如 `<主题>（YYYY-MM-DD）`（处置记录 / 已修 / PlayMode 侧覆盖 / 异常承载 / 会话级复位等） | Input / Pipeline / Asset |

**判据**：答的是「下一轮我要不要重新论证这件事」，而不是「我该怎么用」。把一段内容删掉，使用方会不会写错代码或误判行为？会 → 它属于 README，不属于这里。

## 决策台账的条目格式

**唯一格式**（本目录 23 个模块与 `Documentation/Ledger.md` 的框架级条目同此）：

````markdown
- <状态>：**<一句话结论>**（<YYYY-MM-DD> · <证据>）——<理由>。重开判据：<可判定条件>
````

实例：

````markdown
- 已做：**`DeleteAsync` 在线程池执行同步 `Delete`**（2026-10-15 · `802ca75`）——零接口变更即可让阻塞写离主线程。
- 不做：**不新增「异步删除」可选能力接口**（2026-10-15 · 单议记录）——只有一处调用点，抽象没有第二个实现可对照。重开判据：出现第二个需要异步删除的后端。
- 已推翻：**~~对生效 Provider 探测可选能力接口~~**（2026-09-28 · `e613867`）——装饰器恒实现可选能力接口，探测必然假阳。被 2026-10-11「探测 `_baseProvider`」取代。
````

- **状态词只有六个，逐字**：`已做` / `未做` / `待裁` / `暂不做` / `不做` / `已推翻`。
- **状态写在行首**（`- 未做：`）：状态变化只改行首两三个字，**条目永不移动**——不分小节、不重排，`grep '^- 未做：'` 一次取全部未决。
- **结论**一句话、可判定（「X 走线程池」而不是「优化了 X」）。
- **日期**是做出结论那天，不是改文档那天。
- **证据**：提交号 / 测试类名 / 实测数据 / 探针输出；没有证据的写「依据：<出处>」或标「（推理）」；「用户裁定 / 单议 / 审计结论」也写进括号。
- **理由**从简（一两句为常态）：细节能留在同文件「沿革」节、模块 README 或 `CHANGELOG` 的就留那边，条目只留结论 + 指针；**迁移既有条目时保留原论证，不因格式丢信息**。
- **重开判据**只在 `暂不做`（必带）、`不做`、`待裁` 下写；结构性无判据的写「无重开判据」。
- **`已做` 只收值得下一轮不重新论证的设计结论**（「当时为什么没选另一种」）；纯功能新增归 `CHANGELOG.md`，不在此记账。
- **`已推翻` 保留原文不删**（结论用 `~~删除线~~`），条尾写「被 <日期>『<新结论>』取代」。
- **状态按「该提议的处置」标，不按「现状长什么样」标**：条目主体为「不用 X / 不做 X」时，被处置的是 X 这个提议 ⇒ 取 `不做` / `暂不做`，X 的替代方案是否已落地写进理由。例：Timer 的「不用 `CancellationToken.Register`，改为把令牌存进节点」标 `不做`——被否决的是那个方案，替代方案是现状。否则 `已做` 会混进大量「我们没做某事」，扫描时再也分不清「实现了什么」与「否决了什么」。
- **不写会随开发增长的量**（条数、成员数、行数）——抄进来必然过期。

| 状态 | 含义 | 必带 |
|---|---|---|
| `已做` | 结论已落地 | 证据 |
| `未做` | 还开着，下一轮可开工 | — |
| `待裁` | 需求已知、边界未定，等裁定 | — |
| `暂不做` | 已裁定不做，**判据触发才重开**（判据一族） | 重开判据 |
| `不做` | 结构性不该做 | 无判据的写「无重开判据」 |
| `已推翻` | 原结论被后续证据推翻 | 取代者的日期 + 标题 |

**机械守卫的射程**：`Tools/check-docs.ps1 -Enforce` 的第四条判定守「每个模块有本台账、每条 bullet 的首 token ∈ 上表六个状态词、`Ledger.md` 的模块索引与本目录双向相等」。它**守不住**条目属实、理由正确、状态没写旧——与被守卫的「已知限制」小节同一条边界。
